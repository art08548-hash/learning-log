## 🧩 算法

### 前缀和

<a id="d-prefix-range"></a>
#### D1 区间和 = 两个前缀和之差 ✓
- **结论**：`prefix` 长 n+1、`prefix[0] = 0`，则 `sum(nums[l..r]) = prefix[r+1] - prefix[l]`
- **为什么**：`prefix[r+1]` 是前 r+1 个之和，减去前 l 个之和，剩下的正好是第 l 到第 r 个
- **来源**：2026-11-02 南瓜街；2026-11-03 第 1 关 金库流水账

<a id="d-prefix-hash"></a>
#### D2 子数组和为 k 的个数：前缀和 + 哈希表计数 ✓
- **结论**：区间和 = k ⇔ `prefix_j - prefix_i = k`。遍历时查 `counts[prefix - k]`，初始化 `{0: 1}`，**先查再存**
- **为什么**：
  - `{0: 1}` 代表空前缀，让从第 0 个元素开始的区间也能被数到
  - 先查再存：否则当前位置会和自己配对，把空区间算进来（k = 0 时出错）
- **来源**：2026-11-02 南瓜街（LeetCode 560）

<a id="d-prefix-2d"></a>
#### D3 二维前缀和：递推 + 容斥 ✓
- **结论**：
  - 构建：`P[i+1][j+1] = P[i][j+1] + P[i+1][j] - P[i][j] + M[i][j]`
  - 查询：`P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]`
- **为什么**：上面一块 + 左边一块会把左上角重叠部分算两次，所以减一次；查询时左上角被减了两次，所以加回来一次
- **来源**：2026-11-03 第 2 关 圣水矿脉勘探（独立推出，一次通过）

<a id="d-prefix-mod"></a>
#### D10 余数相同 ⇔ 两个前缀和之差是 k 的倍数 ✓
- **结论**：`p_j % k == p_i % k` ⇔ `(p_j - p_i) % k == 0`。哈希表存「余数 → 出现次数」，初始化 `{0: 1}`
- **为什么**：`p_j = q_j·k + r`，`p_i = q_i·k + r`，相减得 `(q_j - q_i)·k`；反过来也成立，所以是双向等价，计数不漏不多
- **注意**：Python 的 `%` 结果自动非负；C++ / Java 要写成 `(p % k + k) % k`
- **来源**：2026-11-05 第 3 关 药水工坊

<a id="d-prefix-longest"></a>
#### D11 和为 k 的最长子数组：存前缀和第一次出现的下标 ✓
- **结论**：哈希表存「前缀和 → 第一次出现的下标」，初始化 `{0: -1}`；查到 `prefix - k` 就用 `i - 下标` 更新最长；**已经存在就不覆盖**
- **为什么**：
  - 长度 = `i - j`，j 越小越长，所以只留第一次
  - 空前缀在第 0 个元素之前，相当于下标 -1，这样从开头开始的一段长度正好是 `i + 1`
- **来源**：2026-11-05 第 4 关 均势部落战

<a id="d-balance-transform"></a>
#### D12 「两种东西数量相等」→ 一种当 +1、一种当 -1，变成「和为 0」 ✓
- **结论**：数量相等 ⇔ +1 和 -1 抵消 ⇔ 区间和为 0
- **来源**：2026-11-05 第 4 关 均势部落战（**自己想出的**）

<a id="d-diff"></a>
#### D13 差分 = 离散导数，前缀和 = 离散积分 ✓
- **结论**：对差分数组 `diff` 做前缀和，就能还原原数组 `a`，两者互为逆运算（离散版的微积分基本定理）
- **区间加**：要给原数组 `a` 的 `[l, r]` 每个元素都加 v，只改差分数组：`diff[l] += v`，`diff[r+1] -= v`
- **为什么**：整段抬高 v，「导数」只在两个边界上出现 `+v` 和 `-v`，中间是平的
- **来源**：2026-11-05 第 5 关 援军调度（**一眼看出和导数的对应**）

### 排序

<a id="d-merge-sort"></a>
#### D14 归并排序 = 一直对半分到只剩 1 个，再两两 merge 合回去 ✓
- **结论**：0 或 1 个元素天然有序；两个有序列表合并是 O(n)；切 log n 层 × 每层 O(n) = O(n log n)
- **合并**：双指针每次取较小者，相等时先取左边（用 `>` 判断）→ 稳定
- **注意**：递归函数返回新列表，要写 `l = merge_sort(l)`
- **来源**：2026-11-05 排序第 1 关、2026-11-06 排序第 2 关

<a id="d-partition"></a>
#### D16 双指针原地分区（Hoare 风格） ✓
- **结论**：pivot 取末尾；i 从左往右找 > pivot 的，j 从右往左找 < pivot 的，找到就交换；相遇后把 pivot 换到相遇处
- **为什么对**：j 指着的元素始终 >= pivot（开始时是 pivot 本身，之后是刚交换过来的大元素），所以相遇处一定 >= pivot，和末尾交换后不破坏「右边都 >= pivot」
- **只用交换**：每次交换 O(1)，两个指针一共走 n 步，整体 O(n)
- **来源**：2026-11-07 排序第 3 关（**独立想出**）

<a id="d-quick-sort"></a>
#### D17 快速排序：随机 pivot + 终止条件 `l >= r` ✓
- **结构**：`l >= r` 直接返回 → 分区得到 p → 递归 `[l, p-1]` 和 `[p+1, r]`
- **终止条件为什么是 `>=`**：pivot 落在段首时，左段是 `[l, l-1]`，空段的 `l > r`，`l == r` 拦不住
- **随机 pivot**：先把随机位置的元素和段尾交换，分区代码一行都不用改
- **为什么要随机**：有序输入 + 固定选末尾 → 每次只切掉一个，O(n²)，Python 递归深度超限
- **来源**：2026-11-08 排序第 4 关

<a id="d-partition3"></a>
#### D18 三路分区：先把 == pivot 的收到末尾，两路分区后整块换到中间 ✓
- **结论**：
  1. 从 `hi` 往 `lo` 扫一遍，遇到 `== p` 就和 `a[hi - counts]` 交换、`counts += 1` → 所有 `== p` 收到末尾 `[hi-counts+1, hi]`
  2. 对 `[lo, hi-counts+1]` 做两路分区（D16），相遇于 `i`
  3. 此时 `[i, hi]` = 「> p 的一段 + == p 的一段」，对 `r = 0 .. counts-1` 交换 `a[i+r] ↔ a[hi-r]`，`== p` 整块就到了 `[i, i+counts-1]`
- **为什么对**：首尾对称交换时，交换对 `(i+r, hi-r)` 不会碰到之前换过的位置；两段谁长谁短都成立
- **复杂度**：固定扫 3 遍仍是 O(n)；只用交换和几个整数变量，O(1) 空间
- **标准写法**：Dijkstra 三指针一遍扫完，见 [排序笔记 卡 6](sorting.md#卡-6三路分区快排的第二个改进)
- **来源**：2026-11-09 排序附加挑战 三色军团（**自己想出的思路**）

<a id="d-counting-bucket"></a>
#### D15 计数排序 / 桶排序：不靠比较，所以能突破 O(n log n) ✓
- **计数排序**：开一个以「数值」为下标的数组记录个数，再按下标顺序读出来。O(n + k)，k 是数值范围；k 太大时占空间
- **桶排序**：按数值范围分成若干个桶（比如 0～1 万一个桶、1 万～2 万一个桶），桶与桶之间天然有序，桶内部再用别的排序。数据分布均匀时接近 O(n)；全挤在一个桶里时退化成桶内排序的复杂度
- **为什么能比 O(n log n) 快**：O(n log n) 是「只靠两两比较」的下限；这两种排序直接用数值当位置，不做比较
- **哈希表为什么不行**：哈希表的读出顺序和数值大小无关，所以要用「下标 = 数值」的数组
- **来源**：2026-11-07 **自己想出来的**（独立重新发明了计数排序和桶排序）

## 🤖 AI / numpy

<a id="d-np-axis"></a>
#### D5 `axis` = 会消失的那一维 ✓
- **结论**：对 `axis=k` 聚合，shape 里第 k 个数会消失；`keepdims=True` 保留成 1，防止广播错位
- **来源**：numpy 第 3 章

<a id="d-np-broadcast"></a>
#### D6 广播规则 ✓
- **结论**：从最后一维往前对齐，大小为 1 的轴会被拉伸；`(n,)` 按行广播，`(n,1)` 是一列
- **来源**：numpy 第 2 章

<a id="d-weighted-sum"></a>
#### D7 加权和 = 矩阵乘法 ✓
- **结论**：用权重 `w` 对一组向量加权求和，就是 `w @ result`
- **来源**：numpy 第 4 章 4-B

<a id="d-softmax-stable"></a>
#### D8 softmax 先减每行最大值，防止溢出 ✓
- **结论**：`softmax(x) = softmax(x - max(x))`，减掉最大值后 `exp` 不会溢出，结果不变
- **为什么**：分子分母同时乘以 `exp(-max)`，约掉了
- **来源**：numpy 最终 Boss 手写 attention（**自己发现的**）

<a id="d-attention-scale"></a>
#### D9 attention 除以 √d_k ✓
- **结论**：`scores = Q @ K.swapaxes(-1, -2) / sqrt(d_k)`，其中 `d_k = K.shape[-1]`，是特征维，不是词数
- **来源**：numpy 最终 Boss 手写 attention

### 微积分 / 优化

<a id="d-downhill"></a>
#### D19 下山方向 = 斜率的反方向 ✓
- **结论**：站在位置 `w`，损失函数 `L` 在 `w` 处的斜率为正 → 往左走（`w` 变小）`L` 变小；斜率为负 → 往右走。合起来：**往斜率的反方向走，`L` 变小**
- **为什么**：斜率为正表示「往右是上坡」，那往左就是下坡
- **用途**：这就是梯度下降的核心
- **来源**：2026-11-09 数学第 1 关 寻找谷底（一次答对）

<a id="d-argmin-lookup"></a>
#### D20 「让 B 最小的那个 A」= `A[np.argmin(B)]` ✓
- **结论**：两个等长、按下标一一对应的数组 `A`、`B`，在 `B` 里用 `argmin` 找下标，再去 `A` 里取值。例：斜率最接近 0 的位置 = `ws[np.argmin(np.abs(slopes))]`
- **注意**：`argmin` 给的是下标，不是值；找最小的对象是 `B`，取值的对象是 `A`，不要弄反
- **来源**：2026-11-09 数学第 1 关 寻找谷底

<a id="d-chain-rule"></a>
#### D21 链式法则：每一层的斜率在它自己的输入处取值，再全部相乘 ✓
- **结论**：`y = f(g(w))`，记 `u = g(w)`，则 `dy/dw = df(u) · dg(w)`，写成代码是 `df(g(w)) * dg(w)`；三层 `r(q(p(w)))` 是 `dr(q(p(w))) * dq(p(w)) * dp(w)`
- **为什么相乘**：斜率是放大倍数，一级接一级，倍数相乘（`Δy/Δx = Δy/Δu · Δu/Δx`）
- **注意**：外层的斜率代的是里层的**输出** `u`，不是最初的输入 `w`
- **标准做法**：先前向算出并存下 `u`、`v`，反向时直接用，不重复计算（反向传播）
- **来源**：2026-11-10 数学第 2 关 攻城机器的齿轮组（链的结构第一版就写对）

<a id="d-sq-loss-grad"></a>
#### D22 平方损失对 w 的斜率：`d/dw (w·x - y)² = 2 · (w·x - y) · x` ✓
- **结论**：损失 `L = (w·x - y)²`（`x`、`y` 是数据，常数），则 `dL/dw = 2 · (w·x - y) · x`，也就是 `2 × 误差 × 输入`
- **为什么**：外层 `e²` 的斜率是 `2e`，里层 `e = w·x - y` 对 `w` 的斜率是 `x`，链式法则相乘（D21）
- **用途**：线性回归梯度下降里每个数据点贡献的斜率就是它
- **来源**：2026-11-10 数学第 2 关 任务 3（一次写对）

<a id="d-gradient-plane"></a>
#### D23 两个偏导数就能确定所有方向的斜率，梯度方向最陡 ✓
- **结论**：光滑（可微）的函数在一个点附近放大后是一块倾斜的平面；平面的倾斜由两个方向的斜率完全确定，所以朝任意方向 `d`（长度为 1）走的斜率 = `∇f · d`，其中最陡的方向就是梯度 `∇f` 自己的方向，最陡的斜率是梯度的长度
- **为什么**：任意一小步都能拆成「往东 `Δx` + 往北 `Δy`」，海拔变化 ≈ `∂f/∂x · Δx + ∂f/∂y · Δy`，这是梯度和这一步的点积；点积在两者同向时最大
- **注意**：条件是**可微**（光滑），不是连续。`|x|` 连续，但在 0 处是个尖角，放大后不是直线 / 平面
- **来源**：2026-11-10 数学第 3 关学卡 13 时自己追问并推出（360 个方向实测最陡 60°、8.062，和梯度 `[4, 7]` 算出的一致）

<a id="d-mse-grad"></a>
#### D24 均方误差的梯度：`[mean(2 · errs · xs), mean(2 · errs)]` ✓
- **结论**：预测 `w · xs + b`，误差 `errs = w · xs + b - ys`（数组），均方误差 `L = mean(errs²)`，则
  - `∂L/∂w = mean(2 · errs · xs)`
  - `∂L/∂b = mean(2 · errs)`
- **为什么**：单条记录对 `w` 的偏导是 `2 × 误差 × 输入`（D22），对 `b` 的偏导是 `2 × 误差`（里层 `w·x + b - y` 对 `b` 的斜率是 1）；平均值的斜率 = 每条斜率的平均值
- **注意**：`xs` 要乘在 `np.mean` **里面**（先逐条乘，再平均）；常数 2 放里放外都行
- **用途**：线性回归训练时每一步算的就是它
- **来源**：2026-11-11 数学第 3 关 双旋钮校准

<a id="d-gradient-decompose"></a>
#### D25 梯度 = 最陡坡度的正交分解，偏导数 = 它在每个参数方向上的分量 ✓
- **结论**：梯度 `∇f` 是一个向量，方向是最陡上坡，长度是最陡的斜率；把它投影到每个参数的坐标轴上，得到的分量就是这个参数的偏导数（这个参数「该负的责任」）。梯度下降让每个参数各自走 `-lr × 自己的偏导数`，合起来正好是朝最陡下坡走 `lr × 最陡斜率` 那么远
- **注意 1**：各分量按**勾股定理**合成最陡斜率，不是直接相加：`|∇f| = √(∂f/∂w² + ∂f/∂b² + …)`。例：梯度 `[4, 7]` 的最陡斜率是 `√65 ≈ 8.06`，不是 11
- **注意 2**：「责任」只在当前这个点成立，走一步之后地形的倾斜变了，要重新算
- **为什么**：参数的坐标轴两两垂直，向量在垂直轴上的投影就是它的各个分量（D23 里点积 `∇f · d`，`d` 取某条坐标轴的方向时，结果就是那个偏导数）
- **用途**：参数再多也一样，1000 万个参数就是 1000 万维的正交分解
- **来源**：2026-11-11 数学第 4 关开题时自己总结出来

## 📏 约定（不是推出来的，直接记）

这些是人为定的规矩，没有更深的道理，不用推：

- **左闭右开**：Python 的切片 `a[l:r]`、`range(l, r)` 都不包含 r；`a[i:j]` 长度 = `j - i`
- **闭区间 `[l, r]` 换算成切片**：`a[l : r+1]`
- **前缀数组多开一位**：长度 n+1，`prefix[0] = 0`（补在**最前面**，为了 `l = 0` 时不用特判）
- **差分数组多开一位**：长度 n+1，补在**最后面**，为了 `diff[r+1]` 在 `r = n-1` 时不越界；还原时只用前 n 位
- **二维列表**：`[[0] * n for _ in range(m)]`，不能写 `[[0] * n] * m`
- **同时要下标和元素**：`for i, x in enumerate(nums)`，下标在前
- **给循环变量赋值不会改列表**：`for x in nums: x = 0` 无效，要写 `nums[i] = 0`
- **`zip` 按最短的停**；惰性无限计数用 `itertools.count()`
- **函数默认值在定义时只算一次**：要依赖其他参数或是可变对象时，用 `None` 再在函数里补
- **`random.randint(a, b)` 两端都包含**
- **`range(0)`、`range(a, b)` 且 `a >= b` 是空的**：`for` 循环体一次都不执行，长度为 0 的段不用特判
- **`np.linspace(a, b, num)` 两端都包含**，第三个参数是点数；`num` 个点有 `num - 1` 个间隔
- **`np.argmin` / `np.argmax` 返回下标**，不是值
- **列表转 numpy 数组**：`np.array([a, b])`；列表 `* 2` 是重复两遍，数组 `* 2` 才是逐元素乘
- **`...` 和 `pass`**：都能给函数体占位；`...` 是一个值（`Ellipsis`），还能写 `x = ...`，`pass` 是语句不能赋值
- **高维数组转置**：用 `swapaxes(-1, -2)`；`.T` 会反转所有轴

## 🛠️ 写法习惯（Claude 建议的业界标准做法）

通关后对照标准写法时提过的建议，写代码时照着做：

<a id="h-compute-once"></a>
- **H1 中间结果只算一次，存进变量**：同一个表达式要用两次以上，就先起名存下来。例：`errs = w * xs + b - ys`，两个偏导数都用 `errs`；链式法则先前向存 `u`、`v`，反向直接用（反向传播缓存中间值就是这个道理）
  - 来源：2026-11-10 第 2 关（`p(w)` 重复算）、2026-11-11 第 3 关（误差写了两遍）
- **H2 一行只做一件事**：长表达式拆成几行，每行一个有名字的中间量。括号放错、聚合范围包错，几乎都出在一行挤太多东西的时候
  - 来源：2026-11-11 第 3 关（三处失误都在长表达式里）
- **H3 数值求导用中心差分**：`(f(x + h) - f(x - h)) / (2 * h)`，误差和 `h²` 成正比，比前向差分准得多
  - 来源：2026-11-09 第 1 关
- **H4 手算的梯度写完先做 gradient check**：用数值测量仪量一遍，和手算结果对上再往下写
  - 来源：2026-11-10 第 2 关、2026-11-11 第 3 关
- **H5 梯度返回 numpy 数组**：`np.array([dL_dw, dL_db])`，后面才能一行算「旋钮 − 步长 × 梯度」
  - 来源：2026-11-11 第 3 关
- **H6 命名**：
  - 一个数用单数，数组加 `s`：`x` / `xs`、`pred` / `preds`、`e` / `errs`
  - 各级输出叫 `u`、`v`；预测叫 `pred`；误差叫 `e` 或 `err`
  - 斜率 / 偏导数写成 `dL_dw`：下划线前是被影响的量，后是被拧动的量

  - 来源：2026-11-09 第 1 关

## 🔍 写完代码的快速检查清单

思路被打断后容易漏掉的小地方，写完照着扫一遍：

1. **返回值接住了吗？** 调用返回新值的函数（`sorted`、切片、自己写的递归），左边要有 `=`
2. **循环条件方向对吗？** `while` 是「还没完时继续」，不是「完了才进」
3. **下标从哪开始、到哪结束？** 用最小例子（长度 0、1、2）代进去走一遍
4. **变量名有没有用混？** 下标 `i`、元素 `x`、目标 `k` 各管各的
5. **草稿痕迹清掉了吗？** 占位的 `pass`、「待定」之类的过时注释，过了测试再删
6. **只处理一段的函数，扫描范围是 `[lo, hi]` 吗？** 不要写成 `0` 或 `len - 1`
7. **交换写成了赋值吗？** `a[x] = a[y]` 只是复制，`a[y]` 原来的值没地方去 → 士兵被复制一份
8. **要的是下标还是值？** `argmin` / `argmax` / 分区函数返回的是下标，题目要值时还得去数组里取一次
9. **旧代码有没有把变量覆盖掉？** 改题时上一版留下的赋值（比如第二个 `s3 = ...`）会盖住新结果
10. **分式的括号加全了吗？** 先乘除后加减，乘除从左到右：`a - b / 2 * h` 是 `a - ((b / 2) * h)`；分子、分母各套一层括号 `(a - b) / (2 * h)`
11. **返回类型对吗？** 题目要 numpy 数组时，`[x, y]` 要包成 `np.array([x, y])`
12. **聚合函数包住的范围对吗？** `np.mean(a) * b` 和 `np.mean(a * b)` 不一样，先确认哪些东西要在平均**之前**乘进去
