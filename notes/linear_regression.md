## 卡 1：多特征模型

**主角：** 一本账本，`n` 条记录，每条记录有 `d` 个特征。

上一关每条记录只有 1 个特征（城墙等级），模型是 `w × x + b`。现实里影响结果的因素不止一个，每个特征各配一个权重：

```
预测 = x₀ · w₀ + x₁ · w₁ + … + x_{d-1} · w_{d-1} + b
```

- `w₀ … w_{d-1}`：**权重**（weight），每个特征一个，表示「这个特征每多 1，预测多多少」
- `b`：**偏置**（bias），所有特征都为 0 时的预测，就是上一关的「开工费」

**整本账本的写法（业界约定，直接记）：**

| 名字 | 形状 | 含义 |
|---|---|---|
| `X` | `(n, d)` | 特征矩阵：**每一行是一条记录，每一列是一个特征** |
| `y` | `(n,)` | 每条记录的真实值 |
| `w` | `(d,)` | 权重，每个特征一个 |
| `b` | 一个数 | 偏置 |

**为什么 `X` 大写、`y` 小写：** 数学里约定大写字母表示矩阵，小写字母表示向量或数。代码里沿用这个习惯，一眼就能看出谁是二维的。

## 卡 2：随机数生成器与噪声

**主角：** 一个随机数生成器 `rng`。

```python
rng = np.random.default_rng(7)          # 造一个生成器；7 是种子（seed）
rng.integers(1, 16, size=200)           # 200 个随机整数，范围 1～15（右端 16 取不到）
rng.normal(0, 3, size=200)              # 200 个正态分布的随机小数，平均值 0，标准差 3
```

**种子是干什么的：** 生成器其实是一台按固定规则吐数字的机器，种子决定从哪开始吐。种子相同，每次运行得到的「随机数」完全一样。这样你、我、自测拿到的是同一本账本，结果可以复现。

**噪声：** 真实数据不会精确落在任何公式上，总有测不准、说不清的因素。`rng.normal(0, 3, ...)` 模拟的就是这部分：大多数落在 `-3 ~ 3` 之间，偶尔大一点，平均为 0。

**两个拼数组的工具：**

```python
np.column_stack([a, b, c])    # 主角是三个形状 (n,) 的数组：把它们当成三列，拼成形状 (n, 3) 的矩阵
arr.astype(float)             # 主角是数组 arr：返回一个元素都转成小数的新数组
```

## 卡 3：标准化（z-score）

**主角：** 特征矩阵 `X` 的**某一列**（一个特征）。

不同特征的数值范围可能差很多：城墙等级是 1～15，段数是 50～300。**标准化**就是把每一列换算到同一个尺度上：

```
标准化后的值 = (原始值 - 这一列的平均值) / 这一列的标准差
```

换算之后，每一列的平均值都是 0，标准差都是 1。这个换算后的值叫 **z 分数**（z-score），意思是「比平均值高出几个标准差」。

**标准差回顾：** 主角是一组数，衡量它们离平均值有多分散：

```
标准差 = √( (每个数 - 平均值)² 的平均值 )
```

```python
np.std(a)              # 主角是数组 a：所有元素的标准差
np.std(X, axis=0)      # 主角是矩阵 X：沿第 0 轴（行的方向）压缩，每一列得到一个标准差，形状 (d,)
```

`axis=0` 的规则就是 numpy 第 3 章学过的：`axis` 填哪个，形状里那一维就消失。

**为什么要做这一步：** 这一关的任务 4 你会亲眼看到。

### 补充：标准差是什么（2026-11-19 应要求讲）

**主角：** 一组数（比如矩阵的一列）。

标准差回答的问题是：**这组数通常离它们的平均值有多远**，也就是「有多分散」。

两组数平均值都是 150，但分散程度完全不同：

```
A：[148, 149, 150, 151, 152]     ← 挤在 150 附近
B：[50, 100, 150, 200, 250]      ← 散得很开
```

光看平均值分不出它们，标准差就是用来区分这一点的。

**一步步算（以 B 为例）：**

1. 每个数离平均值多远（叫**偏差**）：`[-100, -50, 0, 50, 100]`
2. 想求「平均离多远」，但直接平均偏差得 0：正负抵消了
3. 把每个偏差**平方**，变成正数：`[10000, 2500, 0, 2500, 10000]`
4. 平方的平均值：`5000`。这个数叫**方差**
5. 方差的单位是「段数²」，不好理解，**开根号**换回原单位：`√5000 ≈ 70.7`，这就是**标准差**

A 按同样步骤：偏差 `[-2, -1, 0, 1, 2]`，平方平均 `2`，标准差 `√2 ≈ 1.41`。

所以：**B 的数通常离平均值约 70 段，A 的数通常只离 1.4 左右。**

**为什么用平方，不用绝对值：** 绝对值也能去掉正负号（那样算出来的叫平均绝对偏差），也有人用。平方成为标准做法，主要因为平方处处可以求导、数学性质好。

**和均方误差是一回事：** 方差 = 「用平均值去猜每个数」的均方误差。偏差就是误差，平方再平均，正是 MSE 的公式。

```python
np.std(a)            # 主角是数组 a：所有元素的标准差
np.var(a)            # 方差（标准差的平方）
```

### 补充：标准化的具体例子（2026-11-19 应要求重讲）

**主角：** 账本里的两列。为了好算，只取 5 条记录。

| 记录 | 第 0 列：城墙等级 | 第 1 列：城墙段数 |
|---|---|---|
| 0 | 1 | 50 |
| 1 | 4 | 100 |
| 2 | 7 | 150 |
| 3 | 10 | 200 |
| 4 | 13 | 250 |

两列的数字大小差了几十倍。下面**只对第 1 列（段数）**一步一步做，第 0 列同理。

**第 1 步：减去这一列的平均值** → 回答「这条记录比平均高还是低、差多少」

```
平均值 = (50 + 100 + 150 + 200 + 250) / 5 = 150
每条减去 150：[-100, -50, 0, 50, 100]
```

这一步之后，0 就表示「正好是平均水平」，正数是比平均多，负数是比平均少。

**第 2 步：算这一列的标准差** → 这一列的数字「通常」离平均值有多远

```
上一步的每个数平方：[10000, 2500, 0, 2500, 10000]
平方的平均值：25000 / 5 = 5000
开根号：√5000 ≈ 70.7          ← 这就是段数这一列的标准差
```

先平方再开根号，是为了不让正负抵消（直接平均 `[-100, -50, 0, 50, 100]` 会得到 0）。

**第 3 步：除以标准差** → 换成「以这一列自己的典型波动为单位」

```
[-100, -50, 0, 50, 100] / 70.7 ≈ [-1.41, -0.71, 0, 0.71, 1.41]
```

`1.41` 的意思是：这条记录比平均多了 1.41 个「典型波动」。

**对第 0 列（等级）做同样三步：** 平均值 7，减完是 `[-6, -3, 0, 3, 6]`，标准差 `√18 ≈ 4.24`，除完是 `[-1.41, -0.71, 0, 0.71, 1.41]`。

**两列变成了同一个尺度。** 原来一列是 1～13、一列是 50～250，标准化之后都在 -1.41～1.41 之间。

**放回整个矩阵 `X`（形状 `(n, d)`）：** 每一列**各算各的**平均值和标准差，所以 `mean`、`std` 各有 `d` 个数，形状 `(d,)`，第 `j` 个对应第 `j` 列。矩阵里每个数，减的、除的都是**它所在那一列**的平均值和标准差。

**标准化不改变什么：** 每一列内部的顺序和相对距离不变（记录 4 还是段数最多的，记录 0 和 1 的差距还是记录 1 和 2 的差距），只是换了单位和零点，就像把「摄氏度」换成另一种温标。

## 卡 4：`inf`、`nan` 与 overflow 警告

**主角：** 一个越算越大的数。

小数（`float`）能表示的最大值约是 `1.8 × 10³⁰⁸`。超过它就变成 `inf`（infinity，无穷大），numpy 会打印一条警告：

```
RuntimeWarning: overflow encountered in ...
```

`inf` 再参与运算，比如 `inf - inf`、`0 × inf`，结果无法确定，就变成 `nan`（Not a Number，不是一个数）。

| 值 | 含义 | 判断方法 |
|---|---|---|
| `inf` | 太大，存不下 | `np.isinf(x)` |
| `nan` | 算不出来 | `np.isnan(x)` |
| 正常的数 | | `np.isfinite(x)` 为 `True` |

**注意：** `nan` 和任何数比较大小都是 `False`，连 `nan == nan` 也是 `False`。

**训练中看到它们，几乎总是说明发散了。** 大模型训练日志里看到 `loss: nan`，第一反应就是去查学习率和梯度。

## 卡 5：按容差停止训练

**主角：** 训练循环，和每一步前后的损失。

固定走 `n_steps` 步的问题：事先不知道多少步才够。走少了没到谷底，走多了白费时间。

另一种做法：每走一步，看损失比上一步少了多少。少得几乎可以忽略时，就认为已经到谷底附近了，停下。

```
|这一步之前的损失 - 这一步之后的损失| < tol    →  停
```

- `tol`（tolerance，**容差**）：一个很小的正数，表示「小于这个改进量就不值得继续」
- 同时设一个 `max_steps` 上限，防止永远停不下来（比如学习率太小，每步都只改进一点点却始终大于 `tol`）

**工具：`while` 循环和 `break`**

```python
while 条件:          # 条件为 True 就一直重复
    ...
    if 想停:
        break        # 立刻跳出循环，不管条件
```

**注意：** 「损失几乎不变」不一定说明到了谷底，也可能是学习率太小、走得太慢。所以停下之后，还是要看一眼损失的值合不合理。
