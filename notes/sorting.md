## 卡 1：为什么还要手写排序

Python 自带 `sorted()` 和 `list.sort()`，用的是 Timsort，O(n log n)，实际工作中直接用。

手写排序的意义：
- **面试常考**：快速排序和归并排序要能徒手写出来
- **学的是思想**：两者都基于「分治」，后面的二叉树、回溯也是同一套思路

两个基本概念：
- **比较排序的下限**：只靠两两比较大小来排序，最快只能做到 O(n log n)（已被证明）
- **稳定性**：两个元素一样大时，排序后它们的先后顺序保持不变，这个排序算法就是「稳定」的

## 卡 2：分治和递归

**分治**（divide and conquer）三步：
1. **分**：把大问题拆成几个同类型的小问题
2. **治**：小问题用同样的方法解决（递归调用自己）
3. **合**：把小问题的答案拼成大问题的答案

**递归**必须有：
- **终止条件**（base case）：问题小到可以直接给出答案，比如列表只剩 0 或 1 个元素，已经有序
- **递归调用**：函数调用自己，处理规模更小的问题

⚠️ Python 默认递归深度上限约 1000 层，超过会报 `RecursionError`。

---

## 卡 3：归并排序（Merge Sort）

对一个列表做归并排序：
1. **分**：把列表从中间切成左右两半
2. **治**：对左半边和右半边**分别**做归并排序，得到两个有序列表
3. **合**：把这两个**有序**列表合并成一个有序列表

**为什么是 O(n log n)：**
- 每次对半切，切 log n 层就只剩 1 个元素
- 每一层所有合并加起来处理 n 个元素，O(n)
- 共 log n 层 × 每层 O(n) = O(n log n)

**特点：** 任何输入都是 O(n log n)；**稳定**；合并需要额外 O(n) 空间。
**核心难点：** 合并两个有序列表。

---

## 卡 4：快速排序（Quick Sort）

对一个列表做快速排序：
1. **选基准**：挑一个元素作为基准值 pivot
2. **分区**：把列表排成三部分：比 pivot 小的在左，pivot 在中间，比 pivot 大的在右
3. **递归**：对左边和右边**分别**做快速排序；pivot 已经在最终位置，不用再动

**和归并排序的区别：** 归并是「先分后合」，难点在**合并**；快排是「分完就排好了」，难点在**分区**。

**复杂度：**
- 平均 O(n log n)
- 最坏 O(n²)：每次 pivot 都选到最小或最大值时（比如对已排序列表总是选第一个元素），每次只能切掉一个元素
- 解决办法：**随机选 pivot**

**特点：** 可以原地排序，额外空间小；**不稳定**；实际运行通常比归并排序快。

## 对比

| | 归并排序 | 快速排序 |
|---|---|---|
| 平均复杂度 | O(n log n) | O(n log n) |
| 最坏复杂度 | O(n log n) | O(n²)（随机 pivot 可避免） |
| 额外空间 | O(n) | O(log n)，来自递归栈 |
| 稳定性 | ✅ 稳定 | ❌ 不稳定 |
| 难点 | 合并 | 分区 |

## 卡 6：三路分区（快排的第二个改进）

**问题：** 列表里有大量相等元素时，比如 `[5, 5, 5, ..., 5]`，普通的两路分区会把等于 pivot 的元素全部堆到同一边，每次只切掉一个，快排退化成 O(n²)。随机选 pivot 也救不了：不管选到哪个，值都一样。

**办法：** 把这一段分成**三部分**，而不是两部分：

```
[   < pivot   |   == pivot   |   > pivot   ]
 lo         lt-1  lt      gt   gt+1       hi
```

- 中间那一块（`lt` 到 `gt`）全都等于 pivot，它们**一次性**全部到位
- 接下来只需要对左边 `[lo, lt-1]` 和右边 `[gt+1, hi]` 递归
- 全部相等时：一次分区后左右两边都是空的，直接结束，O(n)

**和两路分区的区别：** 分区函数要返回**两个**边界（`lt` 和 `gt`），而不是一个 pivot 下标。

**名字：** 这个问题也叫「荷兰国旗问题」（Dutch National Flag），因为要把三种颜色的元素分成三段，像荷兰国旗的红、白、蓝三条。

三个指针 `lt`、`i`、`gt` 把 `a[lo..hi]` 分成**四段**，循环中始终保持：

```
[   < p   |   == p   |   还没看   |   > p   ]
 lo   lt-1  lt   i-1   i      gt   gt+1   hi
```

每一步只看 `a[i]`：

| `a[i]` | 操作 | 为什么 |
|---|---|---|
| `< p` | 和 `a[lt]` 交换，`lt += 1`，`i += 1` | 换过来的 `a[lt]` 是已经看过的 `== p`（或 `lt == i` 时就是它自己），所以 `i` 可以前进 |
| `> p` | 和 `a[gt]` 交换，`gt -= 1`，**`i` 不动** | 换过来的 `a[gt]` 还**没看过**，下一轮要重新看 |
| `== p` | `i += 1` | 本来就在中段 |

- 循环条件 `i <= gt`：「还没看」那一段 `[i, gt]` 非空就继续
- 每一步「还没看」都缩短 1 → 一共 n 步，O(n) 时间、O(1) 空间
- pivot 只记**值** `p = a[random.randint(lo, hi)]`，不用换到末尾

**另一种做法（我自己的思路）：** 先扫一遍把 `== p` 的收到末尾 → 两路分区 → 首尾对称交换把整块换到中间。三遍扫描，仍是 O(n)。这和 **Bentley-McIlroy 三路分区**很像（它在分区过程中把相等的收到两头，最后换到中间），C 标准库的一些 `qsort` 实现用的就是它。

**移动一整块的代价：**
- 切片赋值 `a[i:j+1] = a[j:j+1] + a[i:j]`：右边会拼出新列表 → O(k) 额外空间
- `a.insert(i, a.pop(j))`：O(1) 空间，但后面的元素都要挪 → O(n) 时间，放在循环里会变 O(n²)
- 原地只用「交换两个位置」，才能同时做到 O(n) 时间 + O(1) 空间

## 卡 5：非比较排序（计数排序、桶排序）

> 2026-11-07 自己想出来的，见 [D15](derived.md#d-counting-bucket)

| | 思路 | 复杂度 | 局限 |
|---|---|---|---|
| 计数排序 | 数组下标 = 数值，元素 = 出现次数，按下标顺序读出 | O(n + k)，k = 数值范围 | 数值范围大时极占空间；只能排整数这类可以当下标的值 |
| 桶排序 | 按数值范围分桶，桶之间有序，桶内再排序 | 分布均匀时接近 O(n) | 数据扎堆时退化 |
| 基数排序（延伸） | 按个位、十位、百位……依次做稳定的计数排序 | O(d · (n + 10))，d = 位数 | 只适合整数、定长字符串 |

## 其他排序速览

| 排序 | 思路 | 复杂度 | 稳定 |
|---|---|---|---|
| 选择排序 | 每轮找出最大（或最小）的，交换到末尾（或开头） | O(n²) | ❌ |
| 插入排序 | 像理手牌，把新元素插进前面已排好的部分 | O(n²)，几乎有序时接近 O(n) | ✅ |
| 二分插入排序 | 插入排序 + 二分找位置；只省比较，不省挪动 | O(n²) | ✅ |
| 希尔排序 | 先按大间隔做插入排序，再逐步缩小间隔到 1 | 约 O(n^1.3)～O(n²) | ❌ |

**实际库函数都是混合算法：** Python 的 Timsort（归并 + 二分插入）、C++ 的 Introsort（快排 + 堆排 + 插入）。

**原地修改 vs 插入删除：** 交换两个位置 `a[i], a[j] = a[j], a[i]` 是 O(1)；在中间插入或删除是 O(n)，因为后面的元素都要挪。

**快排不稳定的原因：** 交换是长距离跳跃，会让相等的元素越过彼此。

## 思考记录：能不能让选择排序少扫几遍？

> 2026-11-07 自己的想法：每扫一遍，扫出 m 个最大的（记下值和下标）并排好，一次放到末尾

- 复杂度约 O(n² / m)：m 固定时仍是 O(n²)；m ≈ √n 时是 O(n√n)；m = n 就绕回了排序本身
- 坑：把记录的元素换到末尾时，末尾原有元素会被换走，记录的下标可能失效
- **出路**：不要每次重扫，用一个结构一直「记着谁最大」→ **堆**。取最大 O(1)，取走后整理 O(log n)
- **堆排序 = 用堆加速的选择排序**，O(n log n)。学到「堆」模块时接上这里

## 彩蛋：不算排序的「排序」

- **斯大林排序**：遍历一遍，不按顺序的元素直接删掉。O(n) 就「有序」了，但元素丢了
- **猴子排序**（bogosort）：随机打乱，直到碰巧有序。期望 O(n · n!)

排序的定义：**元素一个都不能少，只改变顺序。**
