## 卡 1：为什么还要手写排序

Python 自带 `sorted()` 和 `list.sort()`，用的是 Timsort，O(n log n)，实际工作中直接用。

手写排序的意义：
- **面试常考**：快速排序和归并排序要能徒手写出来
- **学的是思想**：两者都基于「分治」，后面的二叉树、回溯也是同一套思路

两个基本概念：
- **比较排序的下限**：只靠两两比较大小来排序，最快只能做到 O(n log n)（已被证明）
- **稳定性**：两个元素一样大时，排序后它们的先后顺序保持不变，这个排序算法就是「稳定」的

## 卡 2：分治和递归

**分治**（divide and conquer）三步：
1. **分**：把大问题拆成几个同类型的小问题
2. **治**：小问题用同样的方法解决（递归调用自己）
3. **合**：把小问题的答案拼成大问题的答案

**递归**必须有：
- **终止条件**（base case）：问题小到可以直接给出答案，比如列表只剩 0 或 1 个元素，已经有序
- **递归调用**：函数调用自己，处理规模更小的问题

⚠️ Python 默认递归深度上限约 1000 层，超过会报 `RecursionError`。

## 卡 3：归并排序（Merge Sort）

对一个列表做归并排序：
1. **分**：把列表从中间切成左右两半
2. **治**：对左半边和右半边**分别**做归并排序，得到两个有序列表
3. **合**：把这两个**有序**列表合并成一个有序列表

**为什么是 O(n log n)：**
- 每次对半切，切 log n 层就只剩 1 个元素
- 每一层所有合并加起来处理 n 个元素，O(n)
- 共 log n 层 × 每层 O(n) = O(n log n)

**特点：** 任何输入都是 O(n log n)；**稳定**；合并需要额外 O(n) 空间。
**核心难点：** 合并两个有序列表。

---

## 卡 4：快速排序（Quick Sort）

对一个列表做快速排序：
1. **选基准**：挑一个元素作为基准值 pivot
2. **分区**：把列表排成三部分：比 pivot 小的在左，pivot 在中间，比 pivot 大的在右
3. **递归**：对左边和右边**分别**做快速排序；pivot 已经在最终位置，不用再动

**和归并排序的区别：** 归并是「先分后合」，难点在**合并**；快排是「分完就排好了」，难点在**分区**。

**复杂度：**
- 平均 O(n log n)
- 最坏 O(n²)：每次 pivot 都选到最小或最大值时（比如对已排序列表总是选第一个元素），每次只能切掉一个元素
- 解决办法：**随机选 pivot**

**特点：** 可以原地排序，额外空间小；**不稳定**；实际运行通常比归并排序快。

---

## 对比

| | 归并排序 | 快速排序 |
|---|---|---|
| 平均复杂度 | O(n log n) | O(n log n) |
| 最坏复杂度 | O(n log n) | O(n²)（随机 pivot 可避免） |
| 额外空间 | O(n) | O(log n)，来自递归栈 |
| 稳定性 | ✅ 稳定 | ❌ 不稳定 |
| 难点 | 合并 | 分区 |

## 卡 5：非比较排序（计数排序、桶排序）

> 2026-11-07 自己想出来的，见 [D15](derived.md#d-counting-bucket)

| | 思路 | 复杂度 | 局限 |
|---|---|---|---|
| 计数排序 | 数组下标 = 数值，元素 = 出现次数，按下标顺序读出 | O(n + k)，k = 数值范围 | 数值范围大时极占空间；只能排整数这类可以当下标的值 |
| 桶排序 | 按数值范围分桶，桶之间有序，桶内再排序 | 分布均匀时接近 O(n) | 数据扎堆时退化 |
| 基数排序（延伸） | 按个位、十位、百位……依次做稳定的计数排序 | O(d · (n + 10))，d = 位数 | 只适合整数、定长字符串 |

## 其他排序速览

| 排序 | 思路 | 复杂度 | 稳定 |
|---|---|---|---|
| 选择排序 | 每轮找出最大（或最小）的，交换到末尾（或开头） | O(n²) | ❌ |
| 插入排序 | 像理手牌，把新元素插进前面已排好的部分 | O(n²)，几乎有序时接近 O(n) | ✅ |
| 二分插入排序 | 插入排序 + 二分找位置；只省比较，不省挪动 | O(n²) | ✅ |
| 希尔排序 | 先按大间隔做插入排序，再逐步缩小间隔到 1 | 约 O(n^1.3)～O(n²) | ❌ |

**实际库函数都是混合算法：** Python 的 Timsort（归并 + 二分插入）、C++ 的 Introsort（快排 + 堆排 + 插入）。

**原地修改 vs 插入删除：** 交换两个位置 `a[i], a[j] = a[j], a[i]` 是 O(1)；在中间插入或删除是 O(n)，因为后面的元素都要挪。

**快排不稳定的原因：** 交换是长距离跳跃，会让相等的元素越过彼此。

## 彩蛋：不算排序的「排序」

- **斯大林排序**：遍历一遍，不按顺序的元素直接删掉。O(n) 就「有序」了，但元素丢了
- **猴子排序**（bogosort）：随机打乱，直到碰巧有序。期望 O(n · n!)

排序的定义：**元素一个都不能少，只改变顺序。**
